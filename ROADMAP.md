# TrendsFast roadmap

This roadmap is directional, not a delivery promise. A source advances only
when demand, rights, bounded cost, contract tests, and production read-back all
support it.

## v0.1 alpha — implemented fixture-to-founder scope

- product constitution and architecture decisions;
- fixture URL-to-Next-Move path, including `WAIT`;
- canonical evidence receipts and deterministic quality floor;
- persisted, resumable scan lifecycle;
- founder review, private delivery, and feedback;
- honest source status and open metrics surfaces;
- PostgreSQL migrations from zero;
- security boundary tests and launch runbooks;
- public REST contract and API-key foundations;
- persisted processing fences/deadlines and cross-instance auth admission;
- atomic rolling-hour API-key cost admission with fail-safe request reservations;
- 256-bit scan capabilities, pinned website transport, and bounded mutations;
- conservative pre-call model-cost reservations;
- billing-disabled Stripe boundary;
- open-source and distribution materials.

The committed application candidate `072d5fc` passed a frozen install, all eight
migrations, repeat fixture seed, the retention CLI, 277 integration-enabled
tests in 55 files, repository-wide lint/typechecks, broad Prettier, the Drizzle
schema check, optimized build, 28 serialized desktop/mobile browser checks, and
the direct route/status/cache/header matrix. This is local-commit evidence, not
remote CI or deployment verification. Remote CI, deployed public-token edge throttling,
manual accessibility acceptance, scheduled retention execution,
privacy-request operations, model usage/price reconciliation, safe explicit
post-charge retry policy, callable manual-source entry, and OpenAPI error parity
remain v0.1 gates.

External providers remain unverified until actual production read-backs are
recorded. The alpha must not wait on every beta provider if the launch-minimum
panel is genuinely verified.

## v0.1 launch panel, gated independently

1. safe product-site ingestion;
2. Google Trends through the accurately labeled DataForSEO API;
3. Hacker News through Algolia;
4. at least one of X through xAI or Tavily web/news;
5. GitHub and YouTube during the same v0.1 week where feasible;
6. manual founder evidence with audit history.

## After validated demand

- recurring monitoring and a replaceable durable-worker boundary;
- historical snapshots and measured internal velocity;
- managed-cloud operations, scheduled deletion, and export tooling;
- carefully enabled Stripe test-to-live flow;
- thin SDK or CLI only after the REST decision contract stabilizes;
- additional sources only when cohort evidence identifies a missing signal.

## Explicitly not before the first cohort

Automated Reddit ingestion, LinkedIn/Threads/TikTok/Instagram ingestion,
auto-posting, scheduling, social OAuth, content calendars, influencer CRM,
teams, enterprise controls, raw-data resale, credit billing, MCP, mobile apps,
browser extensions, Kafka, Temporal, Redis, Kubernetes, and microservices.

The next single feature after launch should be selected from measured cohort
feedback; the current hypothesis is recurring monitoring for one product, not
another source logo.
