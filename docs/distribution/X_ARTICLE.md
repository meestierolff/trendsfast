## Building products got faster. Choosing what to say did not.

AI coding tools shortened my build loop, but distribution kept reopening the
same tabs. I would search live conversations, demand, developer activity,
competitor launches, news, and video formats. Each source had a different metric
and time horizon. By the end I had collected data, not made a decision.

The tempting shortcut was “put it all in an LLM.” It generated polished ideas,
but polish was not the scarce input. Current, product-specific evidence was.

## The product object is a Next Move

TrendsFast returns one of four actions:

- `PUBLISH` when the founder has a credible, differentiated insight backed by
  independent measured or corroborated evidence;
- `REPLY` when one unusually relevant conversation still has room for a useful
  contribution;
- `REMIX` when a working topic or format can be translated without copying;
- `WAIT` when evidence, relevance, timing, credibility, or coverage is weak.

The result includes a channel, topic, angle, hook, outline, CTA, why-now summary,
signal class, source freshness, original receipts, limitations, confidence, and
valid-until time. It never auto-publishes.

## “Trending” needs an evidence grammar

A single popular post is not velocity. TrendsFast separates external time
series, internal velocity measured from multiple snapshots, independent-source
corroboration, one emerging opportunity, and insufficient signal. Reposts and
articles derived from the same announcement do not become independent by living
on different domains.

## Keep the model away from the receipts

Providers normalize into a canonical stored signal. Deterministic checks handle
recency, relevance, relative source engagement, duplication, lineage,
independence, novelty, saturation, credibility, channel/format fit, and evidence
completeness. Only a compact candidate set reaches structured synthesis.

The model can propose words. It cannot add an evidence URL or metric. The system
binds those from stored records and rejects unsupported claims before founder
review.

## Why fixture-first matters

Fixture mode is not a screenshot mock. It uses the same adapter contracts,
PostgreSQL lifecycle, scoring, evidence, review, delivery, and feedback path,
including provider failure, stale/dependent evidence, and `WAIT`. This makes the
repository useful without asking contributors to buy six accounts.

It also forces an honest distinction: passing fixtures are not production
provider read-backs.
